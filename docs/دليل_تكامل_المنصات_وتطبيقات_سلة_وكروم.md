## 1. مقدمة وأهداف الدليل
يوثق هذا الدليل الاستراتيجيات الهندسية والعملية لنشر وإطلاق محرك البحث الصوتي الذكي باللغة العربية خارج بيئة التجارب الأكاديمية، ودمجه في منظومة التجارة الإلكترونية الحية. يغطي الدليل ثلاثة أنماط رئيسة للنشر:
1. **التكامل المباشر (Direct Integration):** دمج المحرك مباشرة في المتاجر المخصصة المستقلة المبنية بأطر عمل مثل Laravel.
2. **تطبيق متجر سلة (Salla Marketplace App):** توفير المحرك كخدمة سحابية جاهزة للمتاجر عبر منصة "سلة" (Salla).
3. **إضافة متصفح كروم (Google Chrome Extension):** أداة متصفح ذكية موجهة للمتسوقين العرب تعمل تلقائياً فوق أي متجر إلكتروني.

## 2. مسار التكامل المباشر مع المنصات المستضيفة (من الطلب إلى الإطلاق)

يعتمد التكامل المباشر على مبدأ **"التكامل غير الجراحي" (Non-Invasive Architecture)** الموثق في الفصل الثالث (القسم 2.5.3 والمتطلب NFR-02)، حيث لا يُعدل المحرك بنية جداول المتجر المستضيف ولا يتدخل في منطق معاملاته المالية أو بوابات دفعه.

```
                  مسار مراحل التكامل المباشر خطوة بخطوة
┌────────────────┐    ┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│ 1. فحص المتجر  │ ➔  │ 2. ربط التكامل  │ ➔  │ 3. بناء الفهرس   │ ➔  │ 4. الفحص TC..10 │ ➔ 5. الإطلاق العام
└────────────────┘    └─────────────────┘    └──────────────────┘    └─────────────────┘
```

### الخطوة 1: استلام الطلب والتدقيق الأولي (Feasibility & Audit)
* **فحص شهادة الأمان (HTTPS / SSL):** شرط إجباري تفرضه متصفحات الويب الحديثة للسماح لواجهة `Web Speech API` بالنفاذ إلى ميكروفون العميل.
* **فحص بيئة الخادم وقاعدة البيانات:** التحقق من دعم الخادم لـ PHP 8.2+ أو Node.js، وقاعدة بيانات MySQL 8.0+ أو PostgreSQL.
* **تحليل فئات المنتجات:** دراسة طبيعة المنتجات المعروضة لتحديد اللهجات الدارجة المستهدفة (سعودية، يمنية، مصرية، إلخ).

### الخطوة 2: ربط نقاط التكامل الأربع (The 4 Integration Points)
1. **نقطة التكامل الأولى (الواجهة الأمامية):**
   * إدراج ملف `voice-search.js` و `styles.css`.
   * إضافة زر الميكروفون (`#voice-search-btn`) داخل نموذج البحث الحالي بالمتجر.
   * ضبط معالجة غياب دعم التعرف الصوتي (FR-13، TC-09): إخفاء الزر تلقائياً وبقاء البحث النصي دون إظهار أي أخطاء.
2. **نقطة التكامل الثانية (مسار API الموحد):**
   * تسجيل مسار موحد في المتجر: `POST /api/voice-search`.
   * يستقبل نص الاستعلام المنطوق ويعيد مصفوفة المنتجات المطابقة بصيغة JSON.
3. **نقطة التكامل الثالثة (دالة الفهرسة في نموذج المنتج):**
   * إضافة دالة `toSearchableArray()` في نموذج المنتج لتطبيق التطبيع (الجدول 7.3) على الحقول الأربعة (الاسم، الفئة، الخصائص، الوصف).
4. **نقطة التكامل الرابعة (جدول القاموس المستقل):**
   * تنفيذ ملف ترحيل مستقل لإنشاء جدول `lexicon_entries` دون أي مفاتيح خارجية (Foreign Keys) مع جداول المتجر.

### الخطوة 3: التغذية الأولية وبناء الفهرس (Data Ingestion & Indexing)
* استخراج أسماء فئات ومنتجات المتجر وتوليد المرادفات الدارجة الأولية.
* بناء فهرس Meilisearch الأولي وترتيب أوزان الحقول (الاسم > الفئة > الخصائص > الوصف).
* تفعيل المراقبة اللحظية (Observers / Hooks) لتحديث الفهرس عند إضافة أو تعديل أي منتج (FR-08).

### الخطوة 4: الفحص والاعتماد (Testing & Validation)
* تنفيذ حالات الاختبار العشر (TC-01 إلى TC-10).
* قياس زمن الاستجابة (Latency) والتأكد من بقائه تحت ثانية واحدة (NFR-03).

### الخطوة 5: الإطلاق والتدريب (Go-Live & Handoff)
* تسليم لوحة إدارة القاموس لمدير المتجر.
* إطلاق الميزة لـ 20% من العملاء لمراقبة مؤشرات الاستخدام قبل التعميم الكامل.

## 3. معمارية محرك البحث كتطبيق في متجر تطبيقات سلة (Salla App Store)

تُعد منصة "سلة" (Salla) المنصة الرائدة للمتاجر الإلكترونية في منطقة الشرق الأوسط والخليج العربي. تحويل محرك البحث الصوتي إلى **تطبيق معتمد في متجر تطبيقات سلة (Salla App)** يتيح نشره بنقرة زر واحدة لآلاف المتاجر.

```
                      معمارية تطبيق سلة (Salla App Ecosystem)
 ┌─────────────────┐       OAuth 2.0 / Webhooks       ┌────────────────────────┐
 │ متجر سلة المستضيف │  ◄───────────────────────────►  │ خادم محرك البحث الصوتي │
 │ (Merchant Store)│                                  │ (Cloud SaaS Engine)    │
 └────────┬────────┘                                  └───────────┬────────────┘
          │ Inject Twilight Script                                │ Multi-Tenant
          ▼                                                       ▼
 ┌─────────────────┐                                  ┌────────────────────────┐
 │ واجهة المتجر    │ ─── Voice / Text Search API ───► │ فهارس Meilisearch      │
 │ (Shopper UI)    │                                  │ وقاموس مخصص لكل متجر   │
 └─────────────────┘                                  └────────────────────────┘
```

### 3.1 كيف تبدأ العملية من طلب تاجر سلة حتى اكتمال التثبيت؟
1. **تثبيت التطبيق بنقرة واحدة (One-Click Install):**
   * يدخل التاجر إلى "متجر تطبيقات سلة"، ويبحث عن تطبيق "محرك البحث الصوتي الذكي"، ويضغط على "تثبيت".
2. **المصادقة وتفويض الصلاحيات (OAuth 2.0 Handshake):**
   * يُعاد توجيه التاجر إلى شاشة تفويض الصلاحيات (Salla Accounts).
   * يوافق التاجر على منح التطبيق الصلاحيات الضرورية:
     * `products.read` (قراءة بيانات المنتجات).
     * `categories.read` (قراءة الفئات والتصنيفات).
     * `webhooks.read_write` (اشتراك تلقائي في تنبيهات التعديل والحذف).
3. **المزامنة الأولية التلقائية في السحابة (Initial Background Sync):**
   * فور إتمام التفويض، يتلقى خادم محرك البحث رمز الوصول (Access Token).
   * يقوم خادمنا باستدعاء Salla REST API لجلب كافة منتجات المتجر:
     ```http
     GET https://api.salla.dev/admin/v2/products?per_page=100
     ```
   * يُنشئ خادمنا فهرساً مستقلاً للمتجر في Meilisearch (`store_12345_products`) ويطبق قواعد التطبيع والترتيب تلقائياً.
4. **المزامنة الحية المستمرة عبر خطافات الويب (Webhooks Integration):**
   * يشترك خادمنا تلقائياً في أحداث سلة:
     * `product.created`: تطبيع وفهرسة المنتج الجديد فوراً.
     * `product.updated`: تحديث بيانات المنتج وسعره وحالة توفره في الفهرس.
     * `product.deleted`: حذف المنتج من الفهرس.
5. **حقن واجهة البحث الصوتي في متجر التاجر (Twilight Theme App Extension):**
   * لا يحتاج التاجر لكتابة أي كود؛ تقوم سلة بحقن سكربت التطبيق (`twilight-voice.js`) في قالب المتجر.
   * يبحث السكربت عن حقل البحث في الثيم ويحقن زر الميكروفون الأنيق بجانبه مع موجات الصوت التفاعلية.
6. **لوحة تحكم مدمجة للتاجر داخل سلة (Embedded Dashboard):**
   * يفتح التاجر لوحة تحكم التطبيق مباشرة من داخل لوحة تحكم سلة عبر iframe آمن.
   * يستعرض التاجر:
     * إحصائيات البحث الصوتي ومعدل التحويل إلى شراء.
     * الاستعلامات التي لم تعد نتائج (Zero-Results) لإضافة مرادفاتها بنقرة واحدة.
     * إدارة القاموس التجاري المخصص لمتجره.

## 4. معمارية محرك البحث كإضافة لمتصفح جوجل كروم (Google Chrome Extension)

يمثل خيار "إضافة كروم" نقلة استراتيجية مختلفة جذرياً؛ إذ تُركب الإضافة **في متصفح المتسوق نفسه** بدلاً من تثبيتها على خادم المتجر.

```
                   معمارية إضافة متصفح كروم (Client-Side Extension)
┌────────────────────────────────────────────────────────────────────────┐
│ متصفح جوجل كروم (Chrome Browser)                                       │
│                                                                        │
│ ┌────────────────────────┐      DOM Injection     ┌──────────────────┐ │
│ │ متجر إلكتروني عام       │ ◄─────────────────────┤ إضافة كروم الذكية │ │
│ │ (سلة / زد / أمازون / نون)│                       │ (Content Script) │ │
│ └───────────┬────────────┘                        └────────┬─────────┘ │
│             │                                              │           │
│             │ Native Store Submit                          │ SpeechRec │
│             ▼                                              ▼           │
│ ┌────────────────────────┐                        ┌──────────────────┐ │
│ │ نتائج المتجر الرسمية   │                        │ Web Speech API   │ │
│ └────────────────────────┘                        └──────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

### 4.1 نمطا عمل إضافة كروم:

#### النمط الأول: مساعد التسوق الشخصي للمستهلك (Shopper Shopping Companion)
* **الميزة التنافسية الكبرى:** يعمل المحرك على **أي متجر إلكتروني عربي في العالم** (سلة، زد، أمازون، نون، علي إكسبريس، حراج) دون الحاجة لموافقة أو اشتراك أصحاب تلك المتاجر!
* **كيف تعمل الإضافة؟**
  1. يقوم المتسوق بتثبيت الإضافة مجاناً من متجر Chrome Web Store.
  2. بمجرد فتح المتسوق لأي موقع تسوق، يتعرف الـ `content.js` على حقل البحث تلقائياً ويحقن أيقونة الميكروفون المضيئة.
  3. يضغط المتسوق الميكروفون وينطق بلهجته العامية: *"أبغى شنطة ظهر سوداء للجامعة لو سمحت"*.
  4. تقوم الإضافة بمعالجة الصوت، وتطبيع النص، وحذف عبارات الطلب والتأدب، واستبدال الكلمات العامية ("شنطة" ➔ "حقيبة").
  5. تقوم الإضافة بكتابة النص النظيف المحسن (*"حقيبة ظهر سوداء للجامعة"*) داخل حقل بحث المتجر، وتقوم بمحاكاة الضغط على زر Enter أو إرسال النموذج تلقائياً!
  6. يرى المتسوق نتائج المتجر دقيقة وفورية وكأنه كتبها بأفضل صياغة ممكنة.

#### النمط الثاني: أداة التاجر والمطور للمعاينة والتشخيص (Merchant Inspection Tool)
* تتيح للتاجر اختبار أداء البحث الصوتي في متجره، ومحاكاة لهجات متعددة، واستعراض مسار المعالجة (Pipeline Trace Inspector) مباشرة فوق المتجر دون تعديل في الكود المصدري.

## 5. جدول المقارنة المعمارية والتشغيلية بين خيارات النشر الثلاثة

| وجه المقارنة | 1. التكامل المباشر (Direct Integration) | 2. تطبيق متجر سلة (Salla Marketplace App) | 3. إضافة متصفح كروم (Chrome Extension) |
| :--- | :--- | :--- | :--- |
| **الجمهور المستهدف** | المتاجر الكبيرة المخصصة (Enterprise / Laravel). | آلاف التجار المستضافين على منصة سلة وزد. | المتسوقون النهائيون ورواد التجارة الإلكترونية. |
| **طريقة التثبيت** | ربط برمجي للملفات ونقاط التكامل الأربع. | تثبيت فوري بنقرة زر واحدة عبر OAuth 2.0. | تثبيت بنقرة واحدة من Chrome Web Store. |
| **تعديل كود المتجر** | إضافة ملفين ومسار API ودالة الفهرسة. | **صفر تعديل** (حقن تلقائي عبر ثيم Twilight). | **صفر تعديل** (حقن من طرف متصفح المستخدم). |
| **مزامنة البيانات** | عبر أحداث ومراقبي قاعدة بيانات المتجر. | عبر خطافات الويب (Salla Webhooks) آلياً. | تعتمد على الفهرس الداخلي للموقع المزار. |
| **سرعة الانتشار** | متجر بمتجر (B2B Manual). | **فائقة جداً** عبر متجر التطبيقات (B2B SaaS). | **فيروسية للمستهلكين** (B2C Extension). |
| **نموذج الربح المالي** | رسوم ترخيص سنوية أو تكلفة تكامل مخصص. | اشتراك شهري للتاجر (SaaS: مثلاً 99 ر.س/شهر). | مجاني مع خطة مدفوعة للميزات الاحترافية. |
| **التحكم والخصوصية** | تحكم كامل داخل خوادم التاجر. | إدارة متعددة المستأجرين (Multi-Tenant Cloud). | معالجة محلية داخل متصفح المستخدم. |

## 6. بروتوكول الفحص والاختبار الشامل (QA & Cross-Browser Protocol)

لضمان عمل محرك البحث بنسبة **99.99%** عبر المتصفحات والمنصات، يجب الالتزام بقائمة التحقق المعيارية التالية:

```
                              قائمة التحقق الميداني (Checklist)
  [✔] 1. اختبار شهادة SSL/HTTPS لضمان منح إذن الميكروفون دون قيود أمنية.
  [✔] 2. فحص متصفحات سطح المكتب (Chrome, Edge, Firefox, Safari).
  [✔] 3. فحص الهواتف الذكية (Chrome على Android و Safari على iOS).
  [✔] 4. تشغيل حالات التكامل الوظيفي العشر (TC-01 إلى TC-10):
         - TC-01: البحث الصوتي المباشر.
         - TC-02: البحث النصي البديل.
         - TC-03: استبدال الألفاظ العامية بالقاموس.
         - TC-04: تجريد عبارات الطلب والتأدب.
         - TC-05: اختبار التطبيع للأشكال الإملائية المختلفة.
         - TC-06: مطابقة الخصائص وتفضيل الرتب في الترتيب.
         - TC-07: التعامل الأنيق مع انعدام النتائج.
         - TC-08: معالجة الصمت والمهلة الزمنية.
         - TC-09: التحول المتدرج (Graceful Fallback) للمتصفحات غير الداعمة.
         - TC-10: مزامنة تحديث المنتجات الحية مع الفهرس فورياً.
  [✔] 5. قياس زمن الاستجابة (Latency Benchmark):
         - زمن معالجة الخادم < 50 مللي ثانية.
         - زمن الاستجابة الكلي للمتسوق < 1.0 ثانية (معيار نيلسن).
```

## 7. الخلاصة والتوصيات الهندسية للتنفيذ التجاري

1. **المسار الأمثل للتسويق والانتشار السريع:**  
   يُنصح بالبدء بإطلاق **تطبيق متجر سلة (Salla App)** كمنتج رئيسي مستضاف سحابياً (SaaS)، حيث يتيح الوصول المباشر إلى أكثر من 40,000 متجر إلكتروني نشط في السوق السعودي والخليجي دون الحاجة للتفاوض الفردي مع كل متجر.
2. **إضافة كروم كقوة تسويقية مساندة:**  
   إطلاق **إضافة متصفح كروم** للمتسوقين كأداة مجانية ذكية تعمل على جميع المواقع، مما يخلق وعياً مجتمعياً واسعاً بالعلامة التجارية ويضغط على المتاجر للاشتراك في التطبيق الرسمي للحصول على ميزات الفهرسة اللحظية وتخصيص القاموس الداخلي.
3. **التكامل المباشر للمتاجر الكبرى:**  
   الاحتفاظ بمسار **التكامل المباشر (Direct Integration)** لعملاء المؤسسات الكبرى (Enterprise Clients) الذين يمتلكون منصات برمجية مخصصة ويرغبون في استضافة محرك البحث داخل بنيتهم التحتية الخاصة.
