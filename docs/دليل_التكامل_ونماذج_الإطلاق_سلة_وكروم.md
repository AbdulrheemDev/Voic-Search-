## 1. مقدمة وهدف الدليل
يوثق هذا المرجع الهندسي الشامل الإجراءات التنفيذية لنقل محرك البحث الصوتي الذكي من البيئة المعملية إلى بيئات الإنتاج الحية، ويجيب عن التساؤلات المعمارية حول كيفية إتاحة النظام لأصحاب المتاجر والمستهلكين عبر قنوات التوزيع المختلفة:
* **التكامل المباشر:** للمتاجر المستقلة المبنية بأطر عمل مثل Laravel.
* **تطبيق سلة (Salla App):** للمتاجر السحابية المنشأة عبر منصة "سلة" الرائدة إقليمياً.
* **إضافة متصفح كروم (Chrome Extension):** لتمكين المتسوقين من استخدام البحث الصوتي في أي موقع تجارة إلكترونية دون الحاجة لتثبيت أي كود في المتجر.

## 2. دورة حياة التكامل من طلب التاجر حتى التسليم النهائي

تمر عملية إتاحة وتفعيل المحرك لمتجر إلكتروني قائم بست مراحل متسلسلة تضمن عدم انقطاع خدمة المتجر ومطابقة أعلى معايير الجودة:

```
  [1. فحص المتجر] ➔ [2. تهيئة الصلاحيات] ➔ [3. ربط نقاط التكامل] ➔ [4. بناء الفهرس] ➔ [5. اختبار TC-01..10] ➔ [6. الإطلاق والمراقبة]
```

### المرحلة 1: استقبال الطلب والفحص الأولي للبيئة (Readiness Assessment)
1. **استقبال بيانات المتجر:** نطاق المتجر (Domain)، وإطار العمل المستخدم، وحجم الكتالوج (عدد المنتجات والفئات).
2. **فحص المتطلبات الصارمة:**
   * **شهادة الأمان HTTPS (SSL):** شرط إلزامي؛ ترفض متصفحات الويب الحديثة (Chrome, Safari, Edge) تشغيل ميكروفون واجهة `Web Speech API` في صفحات HTTP غير المشفرة.
   * **إصدار بيئة الخادم وقاعدة البيانات:** دعم PHP 8.2+ أو Node.js 20+، ودعم MySQL 8.0+ أو PostgreSQL.

### المرحلة 2: ربط نقاط التكامل الأربع (The 4 Non-Invasive Integration Points)
وفق التصميم المعتمد في الفصل الثالث (القسم 2.5.3 و NFR-02)، يتم الربط دون تعديل بنية الجداول القائمة:
1. **نقطة 1 (الواجهة الأمامية):** حقن مكوّن زر الميكروفون البرمجي (`voice-search.js`) داخل حقل البحث القائم في قالب المتجر.
2. **نقطة 2 (مسار API):** تسجيل مسار موحد `POST /api/voice-search` يستقبل نص الاستعلام ويعيد النتائج بصيغة JSON.
3. **نقطة 3 (دالة الفهرسة والتطبيع):** ربط دالة `toSearchableArray()` في نموذج المنتجات لتطبيع الحقول وتغذية الفهرس.
4. **نقطة 4 (جدول القاموس المستقل):** تشغيل ترحيل جدول `lexicon_entries` المستقل بقاعدة البيانات.

### المرحلة 3: استيراد البيانات وتخصيص القاموس التجاري
* سحب فئات ومنتجات المتجر الحالية لبناء الفهرس المقلوب الأولي.
* تهيئة مداخل القاموس التجاري وفق لهجة الجمهور المستهدف للمتجر (لهجة يمنية، نجدية، حجازية، مصرية، إلخ).
* تفعيل أحداث المزامنة التلقائية (Model Observers / Webhooks) لضمان تحديث الفهرس فورياً عند إضافة أو تعديل المنتجات (FR-08).

### المرحلة 4: التحقق الميداني واختبار حالات التكامل العشر (Testing Protocol)
* تشغيل حزمة الفحص الشاملة للحالات من **TC-01** إلى **TC-10** (انظر القسم 7).

### المرحلة 5: الإطلاق التجريبي (Canary / A/B Rollout)
* تفعيل البحث الصوتي لـ 15-20% من زوار المتجر عبر إعداد التوجيه (Feature Flag).
* مراقبة زمن الاستجابة (Latency) ومعدلات الاستعلامات الصفرية (Zero-Result Queries).

### المرحلة 6: التسليم النهائي والتدريب (Handoff & Monitoring)
* تسليم لوحة إدارة القاموس التجاري وتدريب فريق المتجر.
* تفعيل لوحة المراقبة اللحظية لسجلات البحث الصوتي.

## 3. النموذج الأول: التكامل المباشر المستقل (Native Enterprise Integration)

مخصص للمتاجر الكبيرة والمستقلة المبنية بأطر عمل مخصصة (Custom Laravel / Node.js):
* **طريقة التثبيت:** حزمة Composer/NPM مخصصة تثبت داخل مشروع المتجر:
  ```bash
  composer require voicesearch/arabic-voice-engine
  php artisan voice-search:install
  ```
* **المزايا:** أداء فائق (أقل من 30 مللي ثانية لمعالجة الخادم)، تخصيص كامل للواجهات لتطابق هوية المتجر البصرية، حماية تامة لبيانات المنتجات والعملاء داخل خوادم المتجر الخاصة.
* **العيوب:** يتطلب صلاحيات برمجية مباشرة على خادم المتجر (SSH/Deployment Access).

## 4. النموذج الثاني: محرك البحث كتطبيق في متجر تطبيقات سلة (Salla App Store)

منصة **سلة (Salla)** هي كبرى منصات التجارة الإلكترونية السحابية في المنطقة العربية، حيث تستضيف عشرات الآلاف من المتاجر. تحويل المحرك إلى تطبيق في متجر سلة يتيح لأي تاجر تفعيل البحث الصوتي بنقرة زر واحدة دون كتابة سطر كود واحد.

```
                     معمارية تطبيق سلة السحابي (Multi-Tenant Architecture)
 ┌─────────────────┐       OAuth 2.0       ┌─────────────────────────────────────┐
 │ متجر التاجر في  │ ────────────────────> │ خادم المحرك السحابي المركزي         │
 │ منصة سلة        │ <──────────────────── │ (Voice Search Cloud SaaS)           │
 └─────────────────┘   حقن Script الواجهة  └─────────────────────────────────────┘
         │                                                    │
         │ أحداث المنتجات (Webhooks)                          │ فهارس مستقلة لكل متجر
         ▼                                                    ▼
   product.created / updated ───────────────> [ Tenant Index: Store #10482 ]
```

### 4.1 خطوات التفعيل من منظور صاحب متجر سلة
1. يدخل التاجر إلى **متجر تطبيقات سلة (Salla App Store)**.
2. يبحث عن تطبيق **"البحث الصوتي الذكي بالعربية"**.
3. يضغط زر **"تثبيت التطبيق"**، ويمنح الصلاحيات المطلوبة عبر OAuth 2.0 (`read_products`, `theme_scripts`).
4. **تلقائياً وبشكل فوري:**
   * يسحب خادمنا كتالوج منتجات المتجر وفئاته ويطبق عليها دالة التطبيع وقواعد الفهرسة.
   * يُحقن كود الواجهة وزر الميكروفون في قالب المتجر عبر واجهة سلة للسكربتات (Theme Scripts).
   * يُصبح البحث الصوتي فعالاً في متجر العميل خلال أقل من دقيقتين!

### 4.2 المعمارية التقنية لتطبيق سلة
1. **معمارية المستأجرين المتعددين (Multi-Tenancy):**
   * خادم سحابي مركزي (Cluster) يعزل فهرس كل متجر بمعرف خاص `tenant_id = merchant_id`.
2. **المزامنة اللحظية عبر خطافات الويب (Salla Webhooks):**
   * عند قيام التاجر بإضافة منتج جديد، ترسل سلة طلباً لخطاف الويب `POST /salla/webhooks/product-created`.
   * يتلقى الخادم بيانات المنتج، ويطبّع حقوله، ويحدّث فهرس المتجر فورياً في Meilisearch (تحقيقاً للمتطلب FR-08 و TC-10).
3. **حقن الواجهة دون تعديل القالب (App Script Injection):**
   * عبر معيار سلة لتضمين السكربتات (Theme Scripts API)، يتم تضمين سكربت العميل تلقائياً في ترويسة المتجر لربط زر الميكروفون بحقل البحث.
4. **لوحة تحكم مدمجة (Embedded App Dashboard):**
   * نافذة داخل لوحة تحكم سلة تعرض للتاجر: إحصاءات الكلمات المنطوقة، معدل استخدام الصوت، وأداة سهلة لإضافة كلمات عامية لقاموس متجره الخاص.

## 5. النموذج الثالث: محرك البحث كإضافة في متجر جوجل كروم (Chrome Web Store Extension)

في هذا النموذج، **لا نحتاج إلى موافقة أو تدخل صاحب المتجر نهائياً!** بل نوفر الأداة للمستهلك والمتسوق مباشرة عبر متجر إضافات كروم.

```
                    معمارية إضافة متصفح كروم (Client-Side Injection)
 ┌────────────────────────────────────────────────────────────────────────┐
 │ متصفح المستخدم (Google Chrome)                                         │
 │                                                                        │
 │   صفحة أي متجر إلكتروني (أمازون، نون، متجر سلة، متجر زد، شوبيفاي...)     │
 │   ┌──────────────────────────────────────────────────────────────┐    │
 │   │ شريط البحث: [                      ] [🎙️ زر ميكروفون محقون]  │    │
 │   └──────────────────────────────────────────────────────────────┘    │
 │         ▲                                      │                       │
 │         │ يكتب الكلمات المطبَّعة                 ▼ التقاط الصوت           │
 │         └────── [ وحدة التطبيع والقاموس ] <────── Web Speech API        │
 └────────────────────────────────────────────────────────────────────────┘
```

### 5.1 آلية عمل إضافة كروم
1. يثبت المتسوق إضافة **"Arabic Voice Search Assistant"** من متجر Chrome Web Store.
2. عند زيارة أي متجر إلكتروني (مثل Amazon.sa، Noon، أو أي متجر سلة أو ووكومرس):
   * يقوم سكربت المحتوى (`content.js`) برصد حقل البحث في الصفحة تلقائياً باستخدام خوارزمية ذكية لمحددات DOM.
   * يحقن زر الميكروفون الصوتي الأنيق بجانب شريط البحث في الصفحة.
3. عند ضغط المتسوق على الميكروفون ونطق استعلامه (مثل: *"أبغى شنطة ظهر سوداء لو سمحت"*):
   * تلتقط واجهة `Web Speech API` في المتصفح الصوت.
   * يطبق السكربت قواعد التطبيع السبع (حذف التشكيل، توحيد الألف والتاء).
   * يفرز ويحذف عبارات الطلب والتأدب (*"أبغى"*, *"لو سمحت"*).
   * يستبدل الألفاظ الدارجة عبر القاموس التجاري المدمج (*"شنطة"* ➔ *"حقيبة"*).
   * **يكتب النص المصفى فورياً في شريط بحث المتجر (`حقيبة ظهر سوداء`) ويضغط Enter تلقائياً!**
4. يعرض المتجر للمستخدم النتائج الدقيقة فوراً، وكأن المتجر نفسه هو من يدعم البحث الصوتي الذكي.

## 6. مصفوفة المقارنة المعمارية والتشغيلية بين النماذج الثلاثة

| وجه المقارنة | 1. التكامل المباشر (Native Integration) | 2. تطبيق متجر سلة (Salla App) | 3. إضافة كروم (Chrome Extension) |
| :--- | :--- | :--- | :--- |
| **الجمهور المستهدف** | أصحاب المتاجر الكبرى المستقلة | تجار منصة سلة (آلاف المتاجر) | المتسوقون والمستهلكون النهائيون |
| **طريقة التثبيت** | تضمين كود/حزمة في مشروع المتجر | نقرة واحدة من متجر تطبيقات سلة | تثبيت من متجر Chrome Web Store |
| **تعديل كود المتجر** | إضافة مسار API ومكون واجهة | حقن تلقائي عبر Script API | **صفر تعديل (يعمل في أي متصفح)** |
| **موضع محرك البحث** | داخل خادم المتجر مباشرة | خادم سحابي متعدد المتاجر (SaaS) | في متصفح العميل + API القاموس |
| **سرعة الوصول للسوق** | تعاقد فردي مع كل متجر | وصول فوري لآلاف المتاجر عبر سلة | وصول مباشر لملايين المتسوقين |
| **تزامن كتالوج المنتجات** | مباشر من قاعدة البيانات | عبر خطافات الويب (Webhooks) | يعتمد على محرك بحث المتجر المستهدف |
| **نموذج الإيرادات** | ترخيص مؤسسي أو رسوم إعداد | اشتراك شهري للتاجر (SaaS B2B) | مجاني للمستهلك / عمولات إحالة |

## 7. بروتوكول الاختبار والتحقق وضمان الجودة الميداني

لضمان عمل التكامل بنسبة **99.99%**، يلتزم الفريق بتنفيذ جدول الفحص الميداني التالي قبل اعتماد الإطلاق:

### جدول التحقق الميداني لحالات التكامل العشر (TC-01 إلى TC-10):
```
[TC-01] بحث صوتي مباشر        ➔ التأكد من ظهور المنتج في النتيجة الأولى برتبة صلة قصوى.
[TC-02] بحث نصي يدوي         ➔ التأكد من تطابق النتائج بين الكتابة والصوت.
[TC-03] ألفاظ دارجة مسجلة    ➔ نطق "شنطة/جزمة/موبايل" والتأكد من استبدالها الفوري في الاستعلام.
[TC-04] صيغ طلب وتأدب        ➔ نطق "أبغى... لو سمحت" والتأكد من حذف عبارات الطلب تماماً.
[TC-05] تنوع الرسم الإملائي   ➔ اختبار التاء المربوطة والألف والتأكد من تطابق النتائج 100%.
[TC-06] استعلام مع خصائص     ➔ نطق اسم منتج مع لون/مقاس والتأكد من تصدر المنتج المطابق للخاصية.
[TC-07] استعلام غير موجود     ➔ التأكد من عرض رسالة عربية واضحة وعدم انهيار الصفحة أو إرجاع عشوائي.
[TC-08] صمت دون كلام         ➔ اعتراض خطأ no-speech وعرض توجيه للمستخدم لإعادة المحاولة.
[TC-09] متصفح غير داعم       ➔ التأكد من اختفاء زر الميكروفون بسلاسة وبقاء الحقل النصي.
[TC-10] تعديل اسم منتج       ➔ تعديل منتج والتأكد من تحديث الفهرس اللحظي وظهوره بالاسم الجديد.
```

### معايير الاعتماد النهائي للأداء (Sign-Off Criteria):
1. **زمن الاستجابة (Latency):** الزمن الكلي الإجمالي من انتهاء الكلام حتى ظهور النتائج أقل من **1.0 ثانية**.
2. **توافق المتصفحات:** فحص الأداء على Chrome و Safari و Edge على أجهزة الحاسوب والهواتف الذكية.
3. **أمان البيانات:** تشفير كامل لطلبات البحث، وعدم تخزين تسجيلات صوتية خام تحافظ على خصوصية العميل.
