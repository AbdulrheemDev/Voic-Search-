## (أ) المعمارية المعتمدة

### 1. النمط
معمارية طبقية (Layered Architecture) بأربع طبقات؛ كل طبقة تتعامل مع التي تليها عبر واجهات معلنة (القسم 5.3).

### 2. الطبقات والمكونات (القسم 1.5.3)

| الطبقة | الموضع | المكونات | الدور |
|---|---|---|---|
| طبقة العرض | متصفح المستخدم داخل صفحة البحث في المتجر | واجهة البحث (زر الميكروفون + حقل البحث)، Web Speech API، جزء عرض النتائج | التقاط الكلام وتحويله إلى نص، إرسال الاستعلام، عرض النتائج |
| طبقة التطبيق (Laravel) | خادم المتجر | متحكم البحث، وحدة التطبيع (وحذف عبارات الطلب)، وحدة القاموس، خدمة البحث (عبر Laravel Scout)، نماذج Eloquent | موضع عمل المشروع: معالجة الاستعلام وتنفيذ البحث وإعادة الاستجابة |
| طبقة البحث | خادم Meilisearch | فهرس المنتجات وإعداداته (searchableAttributes، synonyms، typoTolerance، matchingStrategy) | البحث النصي والترتيب والتسامح مع الأخطاء والمرادفات المتكافئة |
| طبقة البيانات | MySQL | جداول المتجر المستضيف + جدول `lexicon_entries` | مصدر بيانات المنتجات والقاموس |

### 3. تدفق الاستعلام (المسار ذو المراحل السبع — القسم 2.3)
1. إدخال الاستعلام بالصوت (أو بالكتابة).
2. تحويل الكلام إلى نص بـ Web Speech API في المتصفح.
3. تطبيع النص وحذف عبارات الطلب في Laravel.
4. تطبيق القاموس التجاري (الاستبدال في Laravel؛ التكافؤ عبر synonyms في Meilisearch).
5. البحث في فهرس Meilisearch عبر Laravel Scout ← معرّفات مرتبة.
6. استرجاع سجلات المنتجات من MySQL عبر Eloquent بالترتيب نفسه.
7. عرض النتائج مرتبة في صفحة المتجر.

مسارات مساندة (القسم 1.2.3): مسار الإدخال النصي يتجاوز المرحلة 2 ويلتحق بالمسار عند الخادم؛ مسار مزامنة الفهرس من MySQL إلى Meilisearch عبر Laravel Scout عند تغير المنتجات.

### 4. الخوارزمية (خوارزمية (1.3))
المدخلات: T (نص الاستعلام)، L (جدول الاستبدال)، S (عبارات الطلب). المخرجات: R (منتجات مرتبة) أو رسالة.
1. T فارغ ← رسالة «لم يُلتقط استعلام» وتوقف.
2. T = تطبيع(T).
3. W = تقطيع(T) إلى كلمات.
4. احذف من W عبارات S ما لم يُفرغ ذلك W.
5. لكل عبارة من كلمتين ثم كل كلمة مفردة في W: إن وُجدت في L استبدلها بمصطلحها المعتمد.
6. Q = كلمات W مفصولة بمسافات.
7. I = معرّفات المنتجات من البحث بـ Q في الفهرس.
8. I فارغة ← رسالة «لا توجد منتجات مطابقة» وتوقف.
9. R = سجلات I من MySQL بترتيب I.
10. أعد R للعرض.

### 5. تدفق البيانات
- **الفهرسة:** جداول المتجر (منتجات، فئات، خصائص، قيم خصائص) ← toSearchableArray في نموذج المنتج (تجميع الحقول الخمسة وتطبيعها) ← Laravel Scout ← فهرس Meilisearch.
- **المرادفات:** مداخل التكافؤ في `lexicon_entries` ← إعداد synonyms في Meilisearch.
- **الاستعلام:** المتصفح ← (HTTP، نص) ← Laravel ← Scout ← Meilisearch ← معرّفات ← Eloquent/MySQL ← (JSON) ← المتصفح.

### 6. الاتصال بين الواجهة والخادم
- طلب HTTP يحمل نص الاستعلام، والاستجابة JSON (القسم 1.5.3).
- لكل منتج في الاستجابة: المعرّف، الاسم، السعر، رابط الصورة، حالة التوفر، رابط صفحة المنتج (القسم 5.6.3).
- **لم يحدد المصدر المعتمد**: مسار الـ URL، طريقة HTTP، شكل JSON الدقيق، رموز الأخطاء، الحماية من الطلبات المتكررة.

### 7. دور قاعدة البيانات
- قراءة بيانات المنتجات دون تعديل بنيتها.
- تخزين القاموس التجاري في `lexicon_entries` (الجدول الوحيد المضاف — القسم 8.3).
- لا تخزين للصوت أو الاستعلامات (NFR-06).

### 8. دور محرك البحث
Meilisearch: فهرسة الحقول الأربعة النصية، الترتيب بقواعد الترتيب (ومنها attribute حسب ترتيب searchableAttributes)، التسامح مع الأخطاء الافتراضي، المرادفات المتكافئة، استراتيجية المطابقة last. يعالج تلقائيًا فصل أداة التعريف وحذف التشكيل للعربية (القسم 6.2.2).

### 9. موضع معالجة النص العربي
- في طبقة التطبيق (Laravel): دالة تطبيع واحدة تُطبق على الاستعلام، ووثائق الفهرسة (داخل toSearchableArray)، ومداخل القاموس (normalized_term، canonical_term).
- حذف عبارات الطلب وتطبيق الاستبدال في Laravel بعد التطبيع.
- معالجة إضافية داخلية في Meilisearch (فصل «ال»، حذف التشكيل).

### 10. آلية عرض النتائج
قائمة مرتبة داخل صفحة البحث؛ بيانات السعر والصورة والتوفر تُقرأ حية من MySQL؛ رسالة عند الاستجابة الفارغة؛ إمكانية تقسيم الصفحات عبر Scout.

### 11. حدود التكامل مع المتجر المستضيف
أربع نقاط تكامل فقط (IR-01..IR-04 في `03_REQUIREMENTS.md`)، ولا تغيير لبنية جداول المتجر أو منطق صفحاته الأخرى.

### 12. نماذج العمليات المعتمدة
- حالات الاستخدام (الشكل (6.3)): الفاعل الرئيس المستخدم؛ الفاعل الثانوي خدمة التعرف في المتصفح؛ الحالات: البحث الصوتي، البحث النصي، استعراض النتائج؛ «تحويل الكلام إلى نص» ضمن البحث الصوتي؛ «معالجة الاستعلام وتطبيق القاموس» ضمن البحثين، وتتضمن «تنفيذ البحث واسترجاع المنتجات».
- مخطط التتابع (الشكل (7.3)): الواجهة ← Web Speech API ← الواجهة ← Laravel (تطبيع، حذف عبارات) ← MySQL (مداخل الاستبدال) ← Laravel ← Scout/Meilisearch (معرّفات) ← MySQL (السجلات) ← الواجهة.

## (ب) معمارية مقترحة لم تُعتمد
- لا توجد معمارية بديلة معتمدة أو مرفوضة في الملف المعتمد.
- عناصر استُبعدت صراحةً في قرارات سابقة (انظر `09_DECISION_LOG.md`): Intent Detection، Entity Extraction، LLM، Vector Search، استخراج الخصائص كمرشحات منظمة، التراجع التدريجي المخصص (إصدار سابق من الفصل الثالث).
